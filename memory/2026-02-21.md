## Bottle Seeker "Zappeln" Bug
**Symptoms**: Robot legs "zappeln" (wildly move) when trying to rotate during bottle search

**Root Cause Found**: In `bottle_seeker.py` Line 209
- Rotate action sent **without** `action_in_progress` flag
- Control loop (10Hz) spammed rotate commands while previous action still running
- Only CENTERING/APPROACHING states had proper action tracking

**Fix Applied**:
```python
# Added to state_searching():
1. Check action_in_progress before sending commands
2. Set action_in_progress = True before rotate
3. Register callback: future.add_done_callback(self._on_action_complete)
```

**Code Changes**:
- `src/hexapod_navigation/hexapod_navigation/bottle_seeker.py`
  - Lines 170-173: Added action_in_progress check in state_searching
  - Lines 208-210: Added action tracking to rotate command

## Second Fix - Race Condition in Search Rotation

**After initial fix, still "zappelt"!** Root cause: Race condition in state_searching()

**Problems Found**:
1. **Line 207**: `current_scan_index = 0` reset BEFORE rotation completed
2. **Line 217**: `last_scan_time = current_time` reset too early
3. **Result**: Next loop iteration sent head commands WHILE robot rotating

**Second Fix Applied** (Commit 115bdb9):
```python
# state_searching() changes:
1. Removed premature head centering (line 199-204)
2. Moved scan_index/scan_time reset to NEW callback
3. Created _on_search_rotate_complete() callback
4. Reduced speed: 40 -> 30, step_size: 5 -> 3

# New callback:
def _on_search_rotate_complete(self, future):
    self.action_in_progress = False
    self.current_scan_index = 0  # NOW reset
    self.last_scan_time = time.time()  # NOW reset
```

**Key Insight**: 
- Generic `_on_action_complete()` only clears flag
- Search needs SPECIAL callback to reset scan state
- Must wait for rotation THEN start new scan cycle
